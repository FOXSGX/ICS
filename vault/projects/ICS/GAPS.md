# ICS 知识缺口

当前有访谈中的待核实细节；整体掌握状态仍为“未评估”。

| 待核实处 | 原始证据 | 下次检验方式 | 状态 |
| --- | --- | --- | --- |
| x86 指令字节中前缀与操作码的顺序 | 用户描述为先读 opcode，再根据前缀读取后续；可能只是口头叙述顺序。指南的指令格式把可选前缀放在 opcode 之前。 | 给出带 `0x66` 前缀的机器码，指出首字节作用与操作数长度。 | 待复核 |
| NEMU 中跳转后的 `eip` 更新机制 | 用户已正确说明 `jmp` 后 `eip` 指向跳转目标；在提示外层会执行 `cpu.eip += len` 后，正确回答跳转处理函数应返回 `0`。 | 开始 PA2-1 后，在实际代码中找到并解释这一处理。 | 口头推理已答对；代码证据待验证 |
| 独立阅读框架与调试的过程能力 | 用户回顾 PA1 时称读懂框架最耗时，调试多由 agent 协助，并担心学不到独立解决问题的方法。用户明确表示手册检索等机械性查找不需要作为个人训练目标。 | 在 PA2-1 中自行解释一条指令的调用路径，并提出一个失败测试的诊断假设；agent 提供所需手册事实与文件位置。 | 用户自述；尚未通过实际任务检验 |
| ISA、CPU 与操作系统的职责边界 | 初次摸底时用户说“ISA 对机器指令进行运行”；经澄清后，能正确判断无 OS 但 CPU 可执行同一 ISA 指令时，加一计算可以完成，而通常的 `printf` 不能原样输出。 | 后续结合系统调用例子再解释库函数、CPU 执行与 OS 服务的分工。 | 基本边界已通过口头情境题；细节待后续检验 |
| 无符号减法与混合类型比较 | 教材例 2.27 中用户最初把 `len=0` 的 `len-1` 当作有符号 `-1`；经解释后正确指出它会回绕成全 1。详见 [概念笔记](../../kb/10-概念笔记/无符号回绕与循环边界.md)。 | 用不同于例 2.27 的混合比较或溢出场景，独立解释实际程序行为。 | 本例已纠正；迁移能力待检验 |
| 同一条加法指令的 OF/CF 与 ISA 语义 | 在两台 CPU 执行 `0x7fffffff+1`、结果位相同但 OF 分别为 1 和 0 的情境中，用户最初认为两者分别是有符号和无符号加法；提示同一条 x86 `ADD` 会更新标志位后，用户正确判断发生有符号溢出，OF 应为 1，OF=0 的 CPU 不符合 ISA。 | 以后用另一条可观察状态不一致的指令独立判断兼容性，并区分 OF 与 CF。 | 经提示修正；独立迁移待检验 |
| 编译与链接的职责边界 | 多文件情境中，用户指出只链接 `main.o`、未加入 `add.o` 会导致失败；同时认为生成目标文件“没有什么条件”。提示编译依赖声明、链接解析定义后，用户提出若仍 undefined reference，应检查是否引用和定义的是同一个符号（例如 `add` 与 `addd`），并推测目标文件地址变化由链接器处理。 | 独立解释符号表中的未定义引用、重定位记录及最终地址修补之间的关系。 | 找到缺失对象与符号名两类原因；正确联想到链接器，机制链待检验 |

仅记录真实回答及可检验的问题；不能仅由资料缺失推断为知识缺口。
