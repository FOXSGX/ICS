# ICS 学习目标

- 课程全称与范围：学校课程；正式课程名称及考核范围待确认。
- 用户目标：跟上学校课程，最终能独立完成 NEMU 大作业。
- 可验证产出：独立完成 NEMU；具体阶段、验收标准和提交要求待确认。
- 截止时间：当前尚不明确。
- 每周时间预算：用户估计约 5 小时。
- 当前掌握状态：未评估。
- 当前项目进度：用户报告 PA1 已完成，课程当前教到 PA2-1，但自己尚未开始 PA2-1；NEMU 整体框架由课程提供，个人主要实现指定函数，包括 PA1-2 的 ALU 部分和 PA1-3 的 FPU 部分。当前任务是完成 PA2-1 和一些笔头作业，具体题目待确认。尚未据此评估概念掌握程度。
- 已观察到的基础：能正确解释 `mov eax, [ebx+4]` 的源地址与目标寄存器；能概述指令执行主线并指出 `jmp` 后 `eip` 应指向跳转目标；能解释 `opcode_entry[opcode](cpu.eip, opcode)` 通过函数指针调用对应处理函数；在给出外层 `cpu.eip += len` 的条件后，正确回答跳转处理函数应返回 `0`。这些是局部口头观察，不能推断对完整寻址或代码实践的掌握。
- 学习困扰：用户回顾 PA1 时认为读懂框架最耗时；调试多由 agent 协助，担心独立能力练习不足。后续应通过本人追踪代码、推断行为和定位具体失败来检验，而非仅凭自评下结论。
- 辅导偏好：对代码理解、推理、实现与调试默认只提示下一步，尽可能增加有价值的本人思考量；手册检索等机械性查找交给 agent，直接提供相关事实和准确出处。
- 考试与标记偏好：期末开卷；讲重要知识点时需要标教材印刷页码，方便在书上标记并复习。
- 教学主线：用户希望由 agent 代替 ICS 老师，围绕已上传的《计算机系统：基于 x86+Linux 平台》系统讲授；NEMU 作为课程实践与理解检验，不作为默认讲授顺序。
- 理论课进度：用户说此前上过一两节课、缺席一节；记得大概讲过硬件、ISA、操作系统和软件的层次结构，可能讲过部分 ISA 指令，但无法确认各节具体内容。不能由 PA1 完成推断已学完教材前两章。
- 初步理解证据：在 ISA 例题中，用户正确指出同一 ISA 的不同 CPU 内部数据流可不同，并认为输出必须相同；需继续区分最终输出与寄存器、内存、标志位等架构可观察状态。
- 数据表示基础观察：用户能直接说明按补码解释时最高位为 1 表示负数，内存不需要额外的有符号标记；基础定义题对用户而言过浅，后续采用能检验运算与程序行为的教材例题。

建议：把每个主题的学习成果关联到自己的解释、练习或复习证据，并与 NEMU 当前阶段对应。此建议尚未成为用户目标。
